# Releasing git-redate

Maintainer runbook. Not part of the docs site; user-facing install
instructions live in `website/docs/install.md`.

Releases are cut locally and pushed by hand: `release.toml` sets
`publish = false` and `push = false`, so `just release` only bumps the
version, regenerates `CHANGELOG.md`, commits, and tags. Pushing the tag
is what starts the release workflow.

## One-time GitHub setup

The repository must be **public**: GitHub Pages on the free tier
requires it, and so does an anonymous `curl` of a release asset.

```
gh auth login
gh repo create qq88976321/git-redate --public --source=. --remote=origin --push
gh run watch                    # the ci workflow should go green
```

Then enable Pages, which cannot be done from a workflow:

**Settings -> Pages -> Build and deployment -> Source: "GitHub Actions"**

`pages.yml` only triggers on changes under `website/`, so kick off the
first deployment by hand:

```
gh workflow run pages.yml
gh run watch
```

The site lands at <https://qq88976321.github.io/git-redate/>, matching
`site_url` in `website/zensical.toml`. Once it deploys, delete the
`STATUS: UNVERIFIED` block at the top of `.github/workflows/pages.yml`.

## Cutting a release

```
just release 0.1.0              # first release: explicit version, not a bump
                                # afterwards: just release patch|minor|major
git push origin master --follow-tags
```

`just release` runs `just gate` through the `pre-release-hook`, so a
failing gate aborts before anything is tagged.

Pushing the `v*` tag runs `release.yml`, which:

1. creates the GitHub Release with notes generated by git-cliff from
   `cliff.toml`, and attaches `install.sh` as an asset;
2. builds four binaries and uploads each as
   `git-redate-<target>.tar.gz` plus a `git-redate-<target>.sha256`
   sidecar.

Verify:

```
gh release view v0.1.0          # expect 9 assets: 4 tarballs, 4 sidecars, install.sh
curl -fsSL https://github.com/qq88976321/git-redate/releases/latest/download/install.sh | sh
git redate --version
```

## Things that will break the installer

`install.sh` hardcodes the asset naming that `release.yml` produces:

- archive `git-redate-<target>.tar.gz` with the binary at its root
  (`leading-dir` left at its default);
- checksum sidecar `git-redate-<target>.sha256` - note it is *not*
  `...tar.gz.sha256` - whose single line names the tarball with no path;
- the four target triples in the docs' platform table.

Change the matrix, the archive name, or the checksum algorithm and
`install.sh` plus both platform tables have to move with it. `just
test-install` catches this locally without needing a release: it builds
the musl asset, lays out the same tree, and drives the installer over
`file://`.

Run before pushing a release:

```
just gate
just lint-sh
just test-install
```
